# 企业级埋点系统整体方案（SDK + 服务端 + 管理后台）

## 一、项目目标

打造一套统一的数据采集平台，支持：

- Taro（微信小程序）
- Taro（支付宝小程序）
- H5
- React
- Vue
- 鸿蒙应用（未来扩展）
- 原生 App（未来扩展）

业务项目只需安装 SDK：

```bash
npm install @company/tracker
```

即可完成埋点接入。

---

# 三、系统组成

## 1. Tracker SDK

负责：

- 自动埋点
- 手动埋点
- 页面埋点
- 曝光埋点
- 队列缓存
- 离线重试
- 批量上传

### 统一接口

```ts
tracker.init()

tracker.track()

tracker.identify()

tracker.pageView()

tracker.flush()
```

---

## 2. Tracker Server

负责：

- 接收埋点数据
- 校验数据格式
- 限流
- 数据清洗
- 写入Kafka

推荐技术：

- NestJS
- Fastify

接口：

```http
POST /api/track/batch
```

---

## 3. Kafka

负责：

- 解耦采集与计算
- 削峰填谷
- 高并发写入

Topic：

```text
track-topic
```

分区策略：

```text
hash(userId)
```

---

## 4. Flink

负责实时计算：

- DAU
- UV
- PV
- 留存
- 漏斗
- 转化率

---

## 5. ClickHouse

负责：

- 用户行为存储
- 实时报表查询

核心表：

```sql
events
```

字段：

```sql
event
user_id
device_id
page
timestamp
properties
```

---

## 6. Tracker Admin

类似神策后台。

功能：

- 事件管理
- 属性管理
- 埋点文档
- 数据查询
- 数据质量监控
- 漏斗分析
- 留存分析

---

# 五、核心事件模型

```ts
interface TrackEvent {

  event: string

  userId?: string

  deviceId: string

  page?: string

  timestamp: number

  properties?: Record<string, any>

}
```

示例：

```json
{
  "event":"habit_checkin",
  "userId":"10001",
  "deviceId":"abc123",
  "page":"pages/checkin/index",
  "timestamp":1717000000,
  "properties":{
      "habitId":"123"
  }
}
```

---

# 六、用户体系

采用双ID模型。

```json
{
  "userId":"10001",
  "deviceId":"abc123"
}
```

## userId

登录后获取。

## deviceId

首次安装生成。

作用：

- 未登录用户统计
- 用户关联分析
- 留存分析

# 七、自动埋点体系

## 页面埋点

自动采集：

```text
page_view
page_leave
```

统计：

- PV
- 页面停留时长
- 跳出率

---

## 点击埋点

推荐声明式埋点：

```tsx

</Button>
```

---

## 曝光埋点

支持：

  "vip_card_show"

- IntersectionObserver
- 微信 createIntersectionObserver
- 支付宝 createIntersectionObserver
